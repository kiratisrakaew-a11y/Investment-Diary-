# วิธีใช้ DCF หลายช่วง (3-stage) และ RIM 5 ปี vs 10 ปี

> ตัวเลขในตัวอย่างทั้งหมดเป็นตัวอย่างประกอบ ไม่ใช่ข้อมูลจริงหรือคำแนะนำ

## 1. DCF หลายช่วง

1. เปิด **ประเมินมูลค่า → ประเมินมูลค่าใหม่** แล้วเลือกวิธี DCF – FCFF หรือ DCF – FCFE
2. ในหัวข้อ **รูปแบบประมาณการ** เลือก **3-stage DCF** (กลับไปใช้แบบเดิมได้ด้วย **Legacy fade**)
   - ครั้งแรกที่สลับ ระบบจะแบ่ง "เส้น fade" ที่ตั้งไว้ (growth / margin ปีแรก → ปีสุดท้าย) ออกเป็น 3 ช่วง 3 + 4 + 3 ปี เพื่อให้เริ่มจากตัวเลขของคุณเอง
   - ปุ่ม **ตัวอย่าง 5 ปี (2+2+1)** และ **ตัวอย่าง 10 ปี (3+4+3)** เป็นโครงตัวอย่างเท่านั้น ควรปรับตัวเลขเอง
3. ตารางช่วง: แต่ละช่วงมีจำนวนปี, growth เริ่ม → จบ และ EBIT margin เริ่ม → จบ ค่าเปลี่ยนเป็นเส้นตรงภายในช่วง
   - Capex, D&A, NWC, ภาษี และ δ (FCFE) ของช่วง: เว้นว่างไว้ = ใช้ค่าหลักในหัวข้อ "การลงทุน" / "ภาษี"
   - เพิ่มได้ถึง 4 ช่วง และต้องมีอย่างน้อย 2 ช่วง รวมกัน 1–20 ปี
4. กราฟเส้นเหนือตารางแสดง growth (เส้นทึบ) และ margin (เส้นประ) รายปีตามช่วง
5. ข้อผิดพลาดจะแสดงเป็นสีแดงและไม่มีมูลค่า (ระบบไม่ปัดค่าให้เอง) เช่น ช่วงเดียว, ปีไม่ใช่จำนวนเต็ม, หรือรวมเกิน 20 ปี
   - คำเตือนสีส้มไม่หยุดการคำนวณ เช่น growth กระโดดระหว่างช่วงเกิน 5 จุด หรือช่วงสุดท้ายจบห่างจาก terminal g
6. Terminal value, mid-year, WACC/Ke และการแปลง EV → มูลค่าหุ้นใช้ชุดเดียวกับแบบเดิม
7. **Scenarios**: เปิด "ใช้ scenarios" แล้วระบบจะสร้าง Bear/Base/Bull รายช่วง (growth ±2 จุด, margin ±15%) ซึ่งเป็นตัวอย่าง
   - แก้ g/M ของแต่ละช่วงได้ และความน่าจะเป็นต้องรวม 100%
8. **Sensitivity** แกน margin / capex / δ ขยับทุกช่วงพร้อมกัน
9. **Reverse DCF** แสดงจำนวนจุดของ growth ที่ต้องบวกหรือลบทุกช่วงจึงจะได้ราคาตลาด

API / MCP: ส่ง `forecastMode: "staged"` และ `stages` ภายใต้ `assumptions` ของ `dcf_fcff` / `dcf_fcfe` (ทั้ง `value_security`, `POST /api/v1/valuation/evaluate`, `save_valuation`)

```json
{ "forecastMode": "staged", "stages": [
  { "name": "High growth", "years": 3, "revenueGrowthStart": 0.12, "revenueGrowthEnd": 0.10, "ebitMarginStart": 0.14, "ebitMarginEnd": 0.15 },
  { "name": "Transition",  "years": 4, "revenueGrowthStart": 0.08, "revenueGrowthEnd": 0.05, "ebitMarginStart": 0.15, "ebitMarginEnd": 0.16 },
  { "name": "Mature",      "years": 3, "revenueGrowthStart": 0.04, "revenueGrowthEnd": 0.03, "ebitMarginStart": 0.16, "ebitMarginEnd": 0.16, "capexPct": 0.04 } ] }
```

## 2. Residual income: 5 ปี vs 10 ปี

1. เลือกวิธี **Residual income** แล้วเปิด "ใช้ประมาณการรายปี (multi_stage)" และกรอก ROE หรือ EPS รายปี
2. การ์ด **เทียบ horizon** จะแสดงผล 5 ปีและ 10 ปีจากข้อมูลชุดเดียวกัน
   - แต่ละ horizon ใช้ h ปีแรก และคิด continuing value ใหม่ที่ปี h
   - ถ้ากรอกไม่ถึง 10 ปี การ์ด 10 ปีจะขึ้น "ข้อมูลไม่พอ" (ระบบไม่เติมปีให้)
3. ตัวเลขในการ์ด: มูลค่า, upside, PV ของ RI, PV continuing value, CV / มูลค่า, implied P/BV, Ke และ ROE หลังปี h
   - ถ้าไม่ระบุ "ROE ระยะยาว" แต่ละ horizon จะใช้ ROE ของปีสุดท้ายของตัวเอง ระบบจะแจ้งไว้ ควรระบุ ROE ระยะยาวเพื่อเทียบบนฐานเดียวกัน
4. กดการ์ดเพื่อเลือก horizon สำหรับกราฟ:
   - **ที่มาของมูลค่า** (waterfall B₀ → RI รายปี → CV → มูลค่า)
   - **ROE เทียบ Ke**
   - **Book value roll-forward** (B ต้นปี + กำไร − ปันผล ± ส่วนปรับ = B ปลายปี)
5. คอลัมน์ "ที่มา" บอกว่ากำไรมาจาก EPS ที่ระบุหรือจาก ROE × B ต้นปี และบอกว่า B ปลายปีเป็นค่าที่ระบุหรือไม่
   - ช่อง "ปรับ" ≠ 0 คือส่วนที่ไม่ผ่านกำไร ซึ่งควรตรวจกับงบจริง
6. **Sensitivity**: มูลค่าตาม ω (persistence) ทั้ง 2 horizon, ตาราง Ke × ROE ระยะยาว และ Ke × g (เฉพาะแบบโตต่อเนื่อง)
   - ช่อง N/A = สมมติฐานใช้ไม่ได้

7. **Scenarios (Bear/Base/Bull)** ใต้การ์ด horizon: เปิด "ใช้ scenarios" แล้วระบบใส่ตัวอย่าง ROE ±2 จุดให้
   - ปรับได้ทั้ง ROE ± (จุด), payout, ROE ระยะยาว และ g ระยะยาว (เฉพาะแบบโตต่อเนื่อง) หรือ ω (เฉพาะแบบ persistence)
   - ความน่าจะเป็นต้องรวม 100% จึงจะแสดงมูลค่าคาดหวัง
   - ปีที่กรอกเป็น EPS จะไม่ถูกปรับด้วย ROE ±
8. **ROE จริงจากงบ**: เติมอัตโนมัติเมื่อกด "เติมสมมติฐานจากงบการเงิน" ใช้เพื่อเตือนเมื่อ ROE ปีแรกต่างเกิน 5 จุดเท่านั้น ไม่มีผลต่อมูลค่า
   - มีคำเตือนเมื่อ payout อยู่นอก 0–100% และเมื่อ EPS ที่กรอกทำให้ ROE ต่างจาก ROE ที่กรอกไว้

API / MCP: `multi_stage_residual_income` และ `value_security` ส่งคืน `horizonComparison`, `persistenceSensitivity`, `sensitivity`, `payoutSensitivity` และ `scenarios` (ส่ง `scenarios` / `historicalRoe` เข้าไปได้); กำหนดช่วงเองได้ด้วย `compareHorizons: [5, 10]`

## 3. วันที่ของข้อมูลและเวอร์ชันสูตร

- ป้าย **วันที่ข้อมูลไม่ตรง** ใช้เกณฑ์จาก **ตั้งค่า → เกณฑ์วันที่ข้อมูลของ valuation** (ค่าเริ่มต้น 180 / 7 / 548 วัน เป็นจุดตั้งต้น ไม่ใช่มาตรฐาน)
  - Rf/ERP/Beta (`inputMeta.asOf`) ลงวันที่หลังวันประเมิน หรือเก่ากว่าเกณฑ์
  - ราคาปิดล่าสุดในระบบ ณ หรือก่อนวันประเมิน ห่างเกินเกณฑ์ (หน้าแก้ไขตรวจเฉพาะเมื่อยังใช้ราคาจากระบบ ราคาที่พิมพ์เองไม่มีวันที่ให้ตรวจ)
  - งบปีบัญชีล่าสุดที่จบก่อนวันประเมิน (ถือว่าสิ้นปี 31 ธ.ค.) เก่ากว่าเกณฑ์
- แสดงที่รายการ valuation ของหุ้น, กล่องผลลัพธ์ในหน้าแก้ไข และหน้าคุณภาพข้อมูล (ตรวจ valuation ล่าสุดของแต่ละหุ้น/วิธี) — เป็นการเตือนเท่านั้น ไม่เปลี่ยนตัวเลข
- valuation ที่บันทึกด้วยสูตรก่อน `2026.10-val6`:
  - ถ้าคำนวณใหม่ได้ค่าเท่าเดิม จะแสดงป้าย "สูตรเวอร์ชันก่อน · ค่าเท่าเดิม" (สีกลาง)
  - ถ้าค่าเปลี่ยน ป้ายจะเป็นสีแดง และหน้าคุณภาพข้อมูลจะเตือน
